# AI Context — Coding Rules

Strict, load-bearing constraints for this codebase. Update this file only
when a global rule actually changes — not for routine feature work.

## Stack & language

- Always write plain JavaScript (`.js` / `.mjs`). Never add TypeScript,
  `.tsx`, or a `tsconfig.json` — there is none, and `jsconfig.json` is the
  only compiler config that exists.
- Always use the App Router (`app/`). Never create a `pages/` directory.
- Always add `'use client'` at the top of any component that uses hooks,
  state, refs, or browser APIs (`sessionStorage`, `Image`, `canvas`, etc.).
  Server-only code (API routes, `lib/`) never gets `'use client'`.
- Always import shared modules through the `@/` path alias
  (`@/lib/...`, `@/app/...`). Never use deep relative paths (`../../..`).

## Styling

- Always style components with inline `style={{ ... }}` objects, matching
  every existing page. Never introduce Tailwind `className` utility classes
  in app code, even though `tailwindcss` is an installed dependency — it is
  unused legacy scaffolding from `create-next-app`, not an active choice.
- Never add a component library or CSS-in-JS package. This is a small,
  single-purpose internal tool — keep the dependency surface minimal.

## Data model — Google Sheets as the database

- Google Sheets is the single source of truth. Always read/write it through
  `getGoogleAuth()` in `lib/google.js`. Never introduce a second persistence
  layer (SQL/Mongo/etc.) without an explicit decision from the user.
- Sheet tabs are accessed by fixed column position (e.g. `Expenses!A:R`,
  `row[11]` = submitted_by). Always treat column order as a strict contract:
  when adding a field, append a new trailing column — never insert or
  reorder columns — and update every route that reads that tab by index
  (`api/submit`, `api/history`, `api/dropdowns`).
- Always run user-entered strings through the `safe()` helper (see
  `app/api/submit/route.js`) before writing them to Sheets with
  `USER_ENTERED`, to prevent formula injection (`=`, `+`, `-`, `@`, `|`).
- Always keep shared enums/maps — roles, statuses, default payee —
  centralized in `lib/constants.js`. Never inline a duplicate of one of
  these maps in a page or route. The category→Xero-tracking-option map is
  the exception: it lives in the Categories tab (column E) because
  projects-pwa reads it too. Never re-create it in code.

## Xero integration

- Xero bills are always created as `DRAFT` `ACCPAY` invoices via
  `createXeroBill` in `lib/xero.js`. Never auto-approve, post, or pay an
  invoice from this app — approval happens in Xero by a human.
- Always wrap Xero calls in try/catch and let the Sheets write proceed even
  if Xero fails, recording `xeroStatus: 'error'`. Never let a Xero outage
  block or lose an expense submission.
- Xero access/refresh tokens live in the "System config" Sheet tab, not in
  environment variables or a secrets manager. Always read/write them via
  `getSheetTokens` / `saveSheetTokens` in `lib/xero.js`. Never hardcode a
  token or commit one to source.
- `scripts/xero-auth.mjs` is the one-off manual flow used to mint the first
  set of tokens. Never run it automatically or wire it into a request path.

## Auth & session

- Login is PIN-only: PINs are stored as `PWA_USER_N = "Name|PIN|role"` rows
  in the "System config" tab and checked in `app/api/auth/route.js`. Never
  add passwords, OAuth login, or a users database without an explicit
  decision — this is intentionally lightweight for a small trusted user base.
- The logged-in user is kept in `sessionStorage` only (`lib/session.js`).
  Never switch to cookies/JWT/NextAuth without an explicit decision, and
  never persist the PIN itself client-side.

## Environment & secrets

- Always read secrets from `process.env` (`.env.local`, gitignored). Never
  commit `.env.local` or paste real credentials/tokens into source, docs, or
  commit messages.

## Build quirks

- `pdfjs-dist` is browser-only. Always keep it externalized for the server
  build in `next.config.mjs` and always load `PdfViewer` via
  `next/dynamic(..., { ssr: false })`. Never import `pdfjs-dist` directly in
  a server component or API route.

## Changelog discipline

- After every code change, always append one line (1–2 sentences max) to
  the `Unreleased` section at the top of `CHANGELOG.md` describing what
  changed. Never add rationale, code excerpts, or file listings there —
  that belongs in `architecture-decisions.md` (if it's a real design
  decision) or is left to `git log`/the diff itself.
- Never let `CHANGELOG.md` entries grow beyond a couple of lines each —
  the goal is a scannable history, not a second commit log.
